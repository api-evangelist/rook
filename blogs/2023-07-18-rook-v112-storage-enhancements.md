<figure><img alt="" src="https://cdn-images-1.medium.com/max/1024/1*pAWsSc5pg6G46hmLeqBBJA.png" /></figure><p>The <a href="https://github.com/rook/rook/releases/tag/v1.12.0">Rook v1.12</a> release is out! v1.12 is another feature-filled release to improve storage for Kubernetes. Thanks again to the community for all the great support in this journey to deploy storage in production.</p><p>The statistics continue to show Rook community growth since the <a href="https://blog.rook.io/rook-v1-11-storage-enhancements-8001aa67e10e">v1.11 release</a> in February:</p><ul><li>10.8K to 11.1K <a href="https://github.com/rook/rook/stargazers">Github stars</a></li><li>278M to 288M Container downloads</li><li>5.8K to 6.1K <a href="https://slack.rook.io/">Slack</a> members</li><li>7.0K to 7.1K <a href="https://twitter.com/rook_io">Twitter</a> followers</li></ul><p>We have a lot of new features for the Ceph storage provider that we hope you’ll be excited about with the <a href="https://github.com/rook/rook/releases/tag/v1.12.0">v1.12 release</a>!</p><h3>Ceph Reef Support</h3><p>Ceph Reef (v18) is the next major version of Ceph that is set to be released any day now. Keeping up with the latest updates to the data plane is critical to Rook so you can always deploy the version of the data plane that you desire. To learn more about all the new features in the Reef release, see the <a href="https://github.com/ceph/ceph/blob/reef/PendingReleaseNotes">pending release notes</a>.</p><p>In addition to Reef, Rook v1.12 continues to support Pacific (v16) and Quincy (v17). In Rook v1.13 we anticipate removing support for Pacific to correspond with its end-of-life from the Ceph team. If you are still running Pacific, we encourage you to <a href="https://rook.github.io/docs/rook/v1.12/Upgrade/ceph-upgrade/">update</a> to the <a href="https://docs.ceph.com/en/latest/releases/#active-releases">latest version of Quincy</a> in the near future.</p><h3>COSI</h3><p>Kubernetes 1.25 included the alpha release for the <a href="https://container-object-storage-interface.github.io/docs/">Container Object Storage Interface (COSI)</a>, allowing applications to provision buckets to PUT and GET objects with an S3 endpoint. To provision a bucket with Ceph RGW, the <a href="https://rook.github.io/docs/rook/v1.12/Storage-Configuration/Object-Storage-RGW/cosi/">Ceph COSI driver</a> is now available and integrated with Rook. The status of the Ceph COSI driver is experimental.</p><p>The COSI driver effectively supersedes bucket provisioning with <a href="https://rook.io/docs/rook/v1.12/Storage-Configuration/Object-Storage-RGW/object-storage/#create-a-bucket">Object Bucket Claims (OBCs)</a> that Rook has provided. In a future release after COSI is declared stable, a path to convert from OBCs will be provided when OBCs will be deprecated.</p><h3>Ceph-CSI v3.9</h3><p>The <a href="https://github.com/ceph/ceph-csi/releases/tag/v3.9.0">v3.9 release</a> of the Ceph-CSI driver is now the version deployed by default with Rook. The driver has a number of important updates to add more storage features available to clients.</p><ul><li>Support added for more efficient selinux relabeling for RBD, CephFS, and NFS drivers</li><li>mkfs options can be set in the storage class</li><li>NFS storage class supports secTypes parameters</li></ul><h3>Node loss</h3><p>If a node goes down where a pod is running with an RWO volume mounted, the volume cannot automatically be mounted on another node. The node must be guaranteed to be offline before the volume can be mounted on another node. Kubernetes 1.26 released an approach to help automate the ability to safely allow these volumes to be mounted on another node.</p><p>A node that is offline must be tainted by the K8s admin after they have verified that the node is indeed unreachable. After the node is tainted, Rook will automatically fence the node, allowing the volume to be mounted on another node. See the Rook documentation on <a href="https://rook.io/docs/rook/v1.12/Storage-Configuration/Block-Storage-RBD/block-storage/#node-loss">handling node loss</a> to enable this new behavior.</p><h3>Minimal Pod privileges</h3><p>While Rook will always require admin privileges to setup the Ceph storage, we strive to use minimal privileges at runtime. In the interest of reducing privileges, we dropped <em>“All” </em>privileges from the operator, CSI driver, and Ceph containers where possible.</p><h3>Krew Plugin</h3><p>The <a href="https://github.com/rook/kubectl-rook-ceph">Rook Krew plugin</a> is a tool we created last year to help troubleshoot and maintain your clusters. The latest addition to the Krew plugin with the <a href="https://github.com/rook/kubectl-rook-ceph/releases/tag/v0.5.2">v0.5 release</a> was a rewrite to use Golang. This will enable more reliable development and testing of features in the future. We hope you are finding this tool useful and look forward to your feedback for what commands will be most helpful to develop!</p><h3>Kubernetes v1.22+</h3><p>Kubernetes v1.22 is now the minimum version supported by Rook, which means we run CI tests against v1.22 and newer. If you still require running an older K8s version we haven’t done anything to prevent running Rook, we simply just do not have any test validation on older versions.</p><h3>Updated Go Dependencies</h3><p>Multiple updates were made to pull in the latest Go dependencies. These are internal updates that aren’t manifest directly in any Rook features, but are important to maintain code hygiene with the latest dependencies.</p><ul><li>Updated to the latest controller runtime APIs with v0.15</li><li>Removed test dependencies on hashicorp vault server packages, which significantly reduced indirect go dependencies. Vault features used by Rook were not affected.</li></ul><h3>What’s Next?</h3><p>As we continue the journey to develop reliable storage operators for Kubernetes, we look forward to your ongoing feedback. Only with the community is it possible to continue this fantastic momentum.</p><p>There are many different ways to get involved in the Rook project, whether as a user or developer. Please join us in helping the project continue to grow on its way beyond the v1.12 milestone!</p><ul><li><a href="https://rook.io/">Rook website</a></li><li><a href="https://github.com/rook/rook">Github</a></li><li><a href="https://slack.rook.io/">Slack</a></li><li><a href="https://twitter.com/rook_io">Twitter</a></li><li><a href="https://www.youtube.com/channel/UCa7kFUSGO4NNSJV8MJVlJAA">Youtube</a></li></ul><img alt="" height="1" src="https://medium.com/_/stat?event=post.clientViewed&amp;referrerSource=full_rss&amp;postId=580bf40f4e58" width="1" /><hr /><p><a href="https://blog.rook.io/rook-v1-12-storage-enhancements-580bf40f4e58">Rook v1.12 Storage Enhancements</a> was originally published in <a href="https://blog.rook.io">Rook Blog</a> on Medium, where people are continuing the conversation by highlighting and responding to this story.</p>
