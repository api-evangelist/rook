<p>The <a href="https://github.com/rook/rook/releases/tag/v1.13.0">Rook v1.13</a> release is out! v1.13 is another feature-filled release to improve storage for Kubernetes. Thanks again to the community for all the great support in this journey to deploy storage in production.</p><p>The statistics continue to show Rook community growth since the <a href="https://blog.rook.io/rook-v1-12-storage-enhancements-580bf40f4e58">v1.12 release</a> in July:</p><ul><li>11.1K to 11.6K <a href="https://github.com/rook/rook/stargazers">Github stars</a></li><li>288M to 304M Container downloads</li><li>6.1K to 6.4K <a href="https://slack.rook.io/">Slack</a> members</li><li>7.1K to 7.3K <a href="https://x.com/@rook_io">X</a> followers</li></ul><p>We have a lot of new features for the Ceph storage provider that we hope you’ll be excited about with the <a href="https://github.com/rook/rook/releases/tag/v1.13.0">v1.13 release</a>!</p><h3>Ceph-CSI v3.10</h3><p>The <a href="https://github.com/ceph/ceph-csi/releases/tag/v3.10.0">v3.10 release</a> of the Ceph-CSI driver is now the version deployed by default with Rook. The driver has a number of important updates to add more storage features available to clients.</p><p><a href="https://rook.github.io/docs/rook/v1.13/Storage-Configuration/Ceph-CSI/ceph-csi-drivers/#enable-read-affinity-for-rbd-and-cephfs-volumes">Per-cluster CSI settings</a> moved from the operator configmap settings to the CephCluster CR, including read affinity and CephFS mount options. In clusters that deploy multiple Ceph clusters, each cluster can now support these CSI options differently per cluster.</p><h3>CephFS Subvolume Groups</h3><p>Subvolume groups for CephFS will now be pinned by default to distribute load across the MDS daemons in predictable and stable ways. If desired, the pinning settings can be configured in the <a href="https://rook.github.io/docs/rook/v1.13/CRDs/Shared-Filesystem/ceph-fs-subvolumegroup-crd/#cephfilesystemsubvolumegroup-spec">CephFilesystemSubvolumeGroup CR</a>.</p><p>By default, a subvolume group named “csi” is created when a CephFilesystem CR is created.</p><h3>Versions</h3><h4>Ceph Pacific Removed</h4><p>Ceph Pacific (v16) is near end of life in the upstream community, thus Rook has now removed support for Pacific.</p><p>Ceph Quincy (v17) and Ceph Reef (v18) are the current supported versions. Before you upgrade to Rook v1.13, make sure you’ve already upgraded to Ceph v17 or newer!</p><h4>Kubernetes v1.23+</h4><p>Kubernetes v1.23 is now the minimum version supported by Rook, which means we run CI tests against v1.23 and newer. If you still require running an older K8s version we haven’t done anything to prevent running Rook, we simply just do not have any test validation on older versions. However, an older version may require removing the new validating admission policies from the Rook CRDs.</p><h3>Admission Policies</h3><p>To improve the validation of Custom Resources (CRs), Validating Admission Policies have now been added to the CRDs. These are a declarative implementation of advanced rules than Rook’s webhook previously implemented. Hooray for declarative rules that allowed us to remove an entire component!</p><p>The policies require K8s 1.25 or greater, so if you’re not already on that version we recommend upgrading to benefit from these validations.</p><p>The webhook is now removed in favor of these rules. The webhook had already been disabled by default for the past few releases due to complexities of certificate management.</p><h3>CephConfig Settings</h3><p>Administrators who need to access to Ceph’s internal settings can now control them with the <a href="https://rook.io/docs/rook/v1.13/CRDs/Cluster/ceph-cluster-crd/#ceph-config"><em>cephConfig</em> section of the <em>CephCluster</em> CR</a>. While these settings aren’t commonly required for configuring a Rook cluster, this allows the admin to declare nearly any advanced setting just as any other Rook setting.</p><p>These advanced Ceph settings were previously able to be set via a <a href="https://rook.io/docs/rook/v1.13/Storage-Configuration/Advanced/ceph-configuration/#custom-cephconf-settings">ceph.conf overrides ConfigMap</a>. The ConfigMap settings are still supported for backward compatibility, in addition to scenarios where mons must have settings applied before they form quorum.</p><h3>Security and Other Enhancements</h3><ul><li>The Ceph exporter daemon was updated to use a Ceph keyring with reduced privileges instead of the admin keyring.</li><li>If the host network setting changes in the CephCluster CR, the mons will need to failover before they pick up the new network settings. Rook will now automatically failover the mons when the host network settings change.</li><li>To allow for advanced maintenance and troubleshooting of Ceph daemons, the label “ceph.rook.io/do-not-reconcile” is now respected for all Ceph daemons. If this label is found on a daemon while the operator is reconciling, the daemon will be skipped. Previously, this label was only available to mons and OSDs.</li></ul><h3>Kubectl Plugin</h3><p>Rook’s <a href="https://github.com/rook/kubectl-rook-ceph">Kubectl plugin</a> continues to be a tool where we are investing to improve troubleshooting scenarios. The latest v0.6 release last month included a new command to restore deleted CRs. We look forward to your feedback on other commands that will help you troubleshoot your clusters!</p><h3>What’s Next?</h3><p>As we continue the journey to develop reliable storage operators for Kubernetes, we look forward to your ongoing feedback. Only with the community is it possible to continue this fantastic momentum.</p><p>There are many different ways to get involved in the Rook project, whether as a user or developer.
